# Motion Principles

AFDS의 모션 시스템은 사용자에게 인터페이스의 **물리적 피드백**을 제공하고, **상태 변화의 인지**를 돕는 것을 목적으로 합니다.
모든 애니메이션은 장식적인 목적보다는 **기능적 목적**을 우선해야 합니다.

## 1. Duration (지속 시간)

애니메이션의 속도는 사용자가 느끼는 시스템의 "경쾌함"과 "안정감"을 결정합니다.

| Token Name | Value     | Description     | Usage Examples                                             |
| :--------- | :-------- | :-------------- | :--------------------------------------------------------- |
| `fast`     | **150ms** | 즉각적인 피드백 | 버튼 클릭, 호버 효과, 토글 스위치, 체크박스                |
| `normal`   | **300ms** | 자연스러운 변화 | 화면 전환, 모달 등장/퇴장, 드롭다운 메뉴                   |
| `slow`     | **500ms** | 큰 규모의 변화  | 페이지 전체 로딩, 복잡한 데이터 시각화, 배경색 서서히 변경 |

## 2. Easing (가속도)

움직임의 성격을 정의합니다.

| Token Name | Cubic Bezier        | Description                 | Usage Examples                                    |
| :--------- | :------------------ | :-------------------------- | :------------------------------------------------ |
| `default`  | `ease-out`          | 시작은 빠르고 끝은 부드럽게 | 대부분의 UI 요소 등장 (모달, 팝오버)              |
| `linear`   | `linear`            | 일정한 속도                 | 로딩 스피너, 색상 변화(Opacity)                   |
| `bounce`   | `cubic-bezier(...)` | 탄성 있는 움직임            | 알림(Toast), 에러 메시지 강조, 강조하고 싶은 버튼 |

## 3. Motion Usage Rules

1.  **Reduce Motion 준수**: 사용자가 시스템 설정에서 "동작 줄이기(Reduce Motion)"를 켰을 경우, 모든 장식적 애니메이션은 비활성화되거나 Fade-in으로 대체되어야 합니다.
2.  **진입과 퇴장**:
    - **진입(Enter)**: 조금 더 빠르게 (`fast` ~ `normal`) 등장하여 사용자를 기다리게 하지 않습니다.
    - **퇴장(Exit)**: 진입보다 조금 더 빠르게 처리하여 작업 완료 느낌을 줍니다.
