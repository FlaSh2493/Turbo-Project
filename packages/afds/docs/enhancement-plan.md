# AFDS 고도화 및 기초 부품 확충 계획 (Enhancement Plan)

이 문서는 AFDS(Agent Friendly Design System)의 기초 브릭을 강화하고, 복합 컴포넌트 조립의 효율성을 극대화하기 위한 상세 실행 계획을 정의합니다.

---

## 1. 목표 (Goal)

- **Base UI 활용 극대화**: 검증된 프리미티브를 사용하여 접근성이 보장된 기초 부품 조기 확충.
- **조립 편의성 향상**: `afds-registry`에서 복잡한 페이지 블록을 '조립'만으로 완성할 수 있는 세밀한 기초 브릭 제공.
- **에이전트 제어력 강화**: UI 구조에 대한 에이전트의 이해도를 높이는 메타데이터 및 패턴 표준화.

---

## 2. 핵심 추진 과제

### 과제 1: Base UI 기반 신규 기초 부품(Bricks) 확충

Base UI의 기능을 래핑하여 디자인 시스템의 '최소 단위 부품'을 추가합니다.

| 컴포넌트           | 활용 프리미티브    | 용도 및 기대 효과                                                       |
| :----------------- | :----------------- | :---------------------------------------------------------------------- |
| **Collapsible**    | Accordion (Single) | 상세 정보 토글, 사이드바 섹션 등 간단한 개폐 로직 조립용                |
| **NumberField**    | Number Field       | 수량, 금액 등 정밀한 숫자 입력 및 증감 로직이 필요한 폼 조립용          |
| **Separator**      | Separator          | 의미론적(Semantic)으로 올바른 레이아웃 구획 정리 및 시각적 구분         |
| **VisuallyHidden** | Utility            | 시각적으로는 숨기되, 에이전트와 스크린 리더에게만 정보를 전달할 때 사용 |
| **FocusTrap**      | Dialog/Popover     | 복합 컴포넌트 내부에서 포커스 이동을 제어하는 보이지 않는 안전 장치     |

### 과제 2: 복합 컴포넌트(Compound) 패턴 전수 적용

이미 구현된 컴포넌트들의 인터페이스를 표준화하여 예측 가능성을 높입니다.

- **대상**: `Drawer`, `DropdownMenu`, `Popover`, `Tooltip` 등
- **수정 내용**:
  - 모든 서브 컴포넌트의 `displayName`을 `Component.Sub` 형태로 통일 (예: `Drawer.Trigger`).
  - `Object.assign`을 통한 통합 익스포트 구조 확립.
  - 예시 코드(JSDoc)를 표준 패턴으로 업데이트.

### 과제 3: 에이전트 친화적 데이터 속성 표준화

에이전트가 UI를 분석하고 수정할 때 '눈' 역할을 하는 속성들을 모든 부품에 강제 적용합니다.

- **속성 세트**:
  - `data-component`: 컴포넌트의 유형 정의 (예: `Select`, `Dialog`)
  - `data-slot`: 컴포넌트 내에서의 역할 정의 (예: `trigger`, `content`, `item`)
  - `data-variant`, `data-size`: 적용된 스타일 상태 명시
- **적용 범위**: Primitives 단계부터 Components 단계까지 전수 전파.

### 과제 4: 지능형 조립 가이드(`Composition Recipes`) 고도화

단순 예시를 넘어 에이전트가 상황에 맞는 UI를 선택하고 조립할 수 있는 논리적 규칙을 문서화합니다.

- **내용**:
  - "위험한 작업(삭제 등)에는 반드시 `Dialog` 확인 패턴을 조합할 것"
  - "데이터가 20개 이상인 선택창은 `Select` 대신 검색이 포함된 `Combobox`를 사용할 것"
  - "로딩 중에는 `Skeleton` 브릭을 사용하여 레이아웃 흔들림을 방지할 것"

## 3. 단계별 실행 로드맵

### 🔵 Phase 1: 부품 확충 및 표준화 (Short-term)

- [ ] Base UI 기반 신규 브릭 구현 — **완료로 표기돼 있었으나 셋 다 그 이름으로 존재하지 않는다.**
      역할이 겹치는 것은 `Accordion`(접힘)·`Divider`(구분선) 이고, 수치 입력 브릭은 없다.
      (문서 import 진실성 가드가 적발했다.)
- [x] 기존 복합 컴포넌트 네이밍 및 데이터 속성 전수 리팩토링 (완료)
- [x] `Composition Recipes` 초안 작성 및 에이전트 학습용 문서화 (완료)

### 🔴 Phase 2: 접근성 및 검증 강화 (Mid-term)

- [ ] `Form` 요소(`Select`, `Combobox`)의 키보드 인터랙션 및 ARIA 스펙 전수 재검증
- [ ] `FocusTrap`, `VisuallyHidden` 등 접근성 유틸리티 컴포넌트 통합

### 🟡 Phase 3: 에이전트 경험 고도화 (Long-term)

- [ ] `llms.txt` 자동 생성 파이프라인 구축
- [ ] 에이전트용 'UI 조립 패턴 라이브러리' 시각화 (Storybook 연동)

---

## 4. 성공 기준 (Success Criteria)

1. **조립 속도**: `afds-registry`에서 신규 페이지 블록 제작 시 커스텀 CSS 작성 비중 10% 미만 유지.
2. **에이전트 인식률**: AI 에이전트가 `data-component` 속성만으로 컴포넌트를 100% 식별 가능.
3. **접근성 점수**: 모든 기초 및 복합 컴포넌트의 키보드 내비게이션 통과율 100%.

---

## 5. 보류 사항 (Excluded for now)

- **Typography 체계화**: 별도 디자인 토큰 동기화 작업 시 진행.
- **DataTable 고도화**: 비즈니스 로직(정렬/필터) 설계 완료 후 진행.
