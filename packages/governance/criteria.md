# 변경 거버넌스 공통 기준

누구나 커밋하고 배포하고 장애에 대응할 수 있게 하는 규칙이다. 사람은 코드를 줄 단위로 읽지 않고, 꼭 필요한 변경에서만 의도와 증거를 확인한다. 나머지는 필수 검사와 위험 판정이 맡는다.

이 문서는 `@turbo-project/governance` 패키지에 들어 있고 레포에 복사하지 않는다. 설치된 버전의 기준은 `pnpm exec governance criteria`로 본다.

## 흐름

```
작성자 쪽 (로컬)
  코드 작성 → 테스트·검사
      │
  pnpm exec governance judge --create <gh pr create 인자>   ← PR을 열 때
  pnpm exec governance judge   ← base를 바꾼 뒤, push할 때마다(pre-push 훅)
      │         1. 열린 PR이 없으면 아무것도 하지 않는다. --create면 판정한 뒤 PR을 연다
      │         2. main으로 가는 PR이면 출처 브랜치를 확인한다. 틀리면 실패로 끝난다
      │         3. 승격·백포트, revert면 low로 끝난다
      │         4. 아니면 새 세션의 Claude가 high·medium 신호와 테스트 없음을 판정한다
      │         5. PR 본문에 `## 위험 등급`, 라벨 risk:low/medium/high, 리뷰어를 붙인다
      │         6. 테스트 없음이면 실패로 끝난다
      ▼
GitHub
  필수 검사 → 머지
        low: 셀프머지
        medium: 리뷰어가 의도와 증거를 확인한다. 머지를 막지는 않는다
        high: CODEOWNERS 오너 1명이 승인해야 머지된다. 메인 오너는 ruleset 우회 목록이라 셀프머지
```

## 원칙

1. 검사를 통과하면 머지해도 안전하다. 안전하지 않았다면 검사를 고친다.
2. 위험은 작성자나 기능이 아니라 변경의 성질로 판단한다.
3. 사람의 판단은 코드가 아니라 수락 기준과 증거에 쓴다.
4. 모든 변경은 한 번에 되돌릴 수 있어야 한다.
5. 장애가 나면 고치기 전에 먼저 되돌린다.
6. 사람, 에이전트, 도구 모두 같은 규칙을 따른다.

## 등급

PR마다 등급을 하나 매긴다. 판정은 PR을 올리는 쪽의 등급 스크립트가 한다. 기준은 diff에서 보이는 것만 쓴다. diff로 알 수 없는 것(서버가 진짜 지우는지, 그 값이 이미 저장돼 있는지)은 판정에 쓰지 않고 리뷰에서 묻는다.

1. 테스트가 증명하지 못하는 변경이면 high
2. 테스트가 판단하지 못하는 변경이면 medium
3. 둘 다 아니면 low

어느 등급이든 동작이 바뀌었는데 그 동작을 확인하는 테스트가 없으면 통과시키지 않는다.

| 작성자    | 등급              | 리뷰어(요청) | 다른 오너(본문 한 줄, 알림 없음)      | 머지 조건                                              |
| --------- | ----------------- | ------------ | ------------------------------------- | ------------------------------------------------------ |
| 누구나    | low               | 없음         | 없음                                  | 셀프머지                                               |
| 팀원      | medium, 피처 오너 있음 | 피처 오너    | 같은 피처의 다른 오너, 기본 오너 전원 | 리뷰어가 수락 기준과 증거를 확인. 머지를 막지는 않는다 |
| 팀원      | medium, 피처 오너 없음 | 메인 오너    | 다른 기본 오너                        | 리뷰어가 수락 기준과 증거를 확인. 머지를 막지는 않는다 |
| 팀원, 메인 오너가 아닌 기본 오너 | high | 메인 오너 | 다른 기본 오너, 피처 오너 | CODEOWNERS 오너 1명이 승인 |
| 기본 오너 | medium            | 없음         | 피처 오너, 다른 기본 오너             | 셀프머지                                               |
| 메인 오너 | high              | 없음         | 피처 오너, 다른 기본 오너             | 셀프머지(ruleset 우회)                                 |

- 기본 오너는 `.github/CODEOWNERS`에 적힌 오너이고, 맨 위 줄의 첫 사람이 메인 오너다. `.github/FEATURE_OWNERS`가 있으면 그 파일의 `*` 줄이 기본 오너다.
- 리뷰어가 여럿이어도 승인은 1명이면 된다. 메인 오너가 없으면 작성자가 다른 기본 오너에게 직접 리뷰를 요청한다.
- 등급은 CODEOWNERS로 정하지 않는다. CODEOWNERS는 GitHub가 high 경로의 머지를 막는 데와 오너를 찾는 데만 쓴다. ruleset에서 Code Owner 승인 필수를 켜고, 메인 오너는 우회 목록에 둔다. GitHub는 자기 PR을 자기가 승인하게 두지 않으므로, high를 셀프머지할 수 있는 사람은 우회 목록에 있는 메인 오너뿐이다.
- high로 판정됐는데 바뀐 파일이 CODEOWNERS에 없으면 GitHub가 막지 않는다. 판정 근거에 그 파일을 적으니, 맞으면 CODEOWNERS에 더한다.

승인은 그 커밋에만 유효하다. 승인 뒤 새 커밋이 올라오면 다시 받는다. 봇이나 AI의 승인은 사람 승인으로 세지 않는다.

### high: 테스트가 증명하지 못하는 변경

테스트는 개발자 PC나 CI에서만 돈다. 실제 서버에서만 문제가 드러나거나 검사 자체를 바꾸는 변경이다. 아래 표부터 테스트 없음 표까지 새 세션의 Claude가 판정한다. 등급 스크립트가 이 표들을 그대로 읽어 판정 기준으로 쓴다.

| 키         | 신호                     | 켜지는 경우 |
| ---------- | ------------------------ | ----------- |
| untestable | 테스트가 증명하지 못함 | 다음 중 하나를 바꾼다. (1) CI·배포 설정 (2) 빌드·서버 실행 설정 (3) 모든 요청이 거쳐 가는 코드(로그인 체크, 프록시, 미들웨어) (4) 의존성 메이저 버전 (5) 환경변수를 새로 쓰거나 이름·뜻을 바꾼다. 의존성 패치·마이너 업데이트, 테스트·문서만 바꾼 것은 없음이다. |

### medium: 테스트가 판단하지 못하는 변경

테스트는 만든 대로 돌아가는지만 본다. 그렇게 만들어도 되는지는 사람이 정해야 하고, 그 판단이 틀리면 되돌리기 어려운 변경이다.

| 키              | 신호                 | 켜지는 경우 |
| --------------- | -------------------- | ----------- |
| wider-access    | 권한이 넓어짐        | 누가 무엇을 보고 할 수 있는지의 범위를 넓힌다. role 조건을 지우거나 허용 목록에 더한다. 좁히는 것, 화면 문구·스타일만 바뀐 것은 없음이다. |
| external-effect | 밖에서 실제로 일어남 | 결제, 메일·메시지 발송, 다른 서비스에 쓰는 호출을 새로 만들거나 그 호출이 언제 일어나는지를 바꾼다(버튼 클릭에서 저장 시점으로 옮기는 등). 이미 있는 호출의 문구·표시만 바꾼 것, 읽기만 하는 호출은 없음이다. |
| bulk-change     | 한 번에 여러 개      | 여러 대상을 한 번에 바꾸거나 지우는 기능을 새로 만들거나 그 대상을 넓힌다. id 하나를 보내던 요청이 목록을 보내게 되거나, 반복문 안에서 쓰기 요청을 보낸다. 하나씩 처리하는 생성·수정·삭제는 없음이다. |
| stored-format   | 이미 나간 것과 안 맞음 | 이미 저장되는 값(브라우저 저장소, 쿠키, DB에 그대로 들어가는 값)이나 밖에 알려진 주소(로그인 콜백, 공유 링크의 경로와 쿼리)의 이름이나 모양을 바꾼다. 새로 추가만 하는 것은 없음이다. |
| new-pattern     | 새 패턴              | 다른 코드가 따라 쓸 구조를 처음 만들거나 바꾼다. 새 라이브러리를 들인다, 앱 전체를 감싸는 Provider·Context를 더한다, 이미 있는 방식(HTTP 클라이언트, 폼, 상태 관리)과 같은 일을 하는 두 번째 방식을 만든다, 여러 파일이 쓰는 함수·컴포넌트의 인자·반환값·동작을 바꾼다. 이미 있는 방식대로 하나 더 만든 것, 쓰는 곳이 하나뿐인 공용 코드, 사용법이 그대로인 내부 정리는 없음이다. |

### 테스트 없음

| 키           | 신호        | 켜지는 경우 |
| ------------ | ----------- | ----------- |
| missing-test | 테스트 없음 | 동작이 바뀌었는데 바뀐 동작을 확인하는 테스트가 이번 diff에 없다. 동작이 그대로인 정리·이름 바꾸기, 문서·설정·스타일만 바꾼 것, 테스트로 확인할 수 없는 CI·배포 설정은 없음이다. |

아래는 기계가 정한다.

- 위험 판정 없음: Claude 판정을 얻지 못했다(claude CLI가 없거나 실패). medium으로 둔다.
- 테스트 없음이 있음이면 `governance judge`가 실패로 끝난다. `--create`면 PR을 만들지 않고, 열린 PR이면 본문에 등급과 근거를 붙인 뒤 실패로 끝난다. 테스트를 더해 다시 돌린다.

판정 결과는 커밋 SHA와 함께 PR 본문 맨 위(첫 섹션 앞)의 `## 위험 등급`에 붙는다. 판정이 틀렸다고 보면 PR에 이유를 남기고 본문을 고친다.

### low

위 신호가 하나도 없는 변경, 보호 브랜치(`main`, `develop`, `staging`)끼리 오가는 같은 레포의 승격·백포트 PR, 원래 PR이 이 레포에서 머지된 revert PR. 승격·백포트와 revert는 Claude 판정 없이 low다.

revert PR은 high 경로를 되돌리는 경우에도 low다. 되돌리기를 늦추지 않는다. CODEOWNERS 경로를 되돌리면 GitHub의 Code Owner 승인은 걸리므로, 장애 중이면 메인 오너가 우회해서 머지한다.

## main으로 가는 PR

`main`으로는 보호 브랜치(`develop`, `staging`)나 `hotfix/*`, `release/*`에서만 PR을 연다. 체리픽이나 운영 버그 수정도 `hotfix/*`로 보낸다. 출처가 틀린 PR에는 `governance judge`가 등급을 붙이지 않고 실패로 끝나며, base를 바꾼 뒤 다시 돌리면 된다. `--create`로 열 때는 PR을 만들지 않고 실패로 끝난다. 웹이나 `gh`로 직접 여는 것은 막지 않는다.

## revert

revert PR 본문에 원래 PR과 되돌린 이유를 쓴다(PR 템플릿의 revert 칸). 원인 분석은 사용자에게 영향이 간 장애이거나 같은 일이 반복될 때만 하고, 결과는 테스트·lint·위험 신호 중 하나로 남긴다.

## 적용 뒤 사람이 할 설정

브랜치 보호(ruleset)를 보호 브랜치에 건다. 켜는 순간 팀의 머지 방식이 바뀌므로 팀에 알리고 켠다.

- PR 필수, 직접 푸시 금지
- 필수 검사: 이 레포의 CI 검사
- 필요 승인 수 0, Code Owner 승인 필수
- 메인 오너를 우회 목록(bypass)에 넣는다

## 기준 개정

- low로 머지한 변경이 되돌려지면 그 유형을 신호에 더할지 본다. 더할 때는 diff에서 보이는 말로 쓴다.
- 사람이 보는 PR(medium·high)이 너무 많으면 원인이 된 신호가 너무 넓게 쓰였는지 본다. `gh pr list --label risk:medium`으로 찾는다.
- 레포만의 개정은 CODEOWNERS를 고치는 PR로, 모든 레포의 개정은 이 문서를 고치는 turbo-project PR로 한다.
