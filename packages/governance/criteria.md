# 머지 기준

사람은 PR 코드를 리뷰하지 않는다. 에이전트가 아래 조건을 채울 때까지 작업하고, 머지 게이트가 같은 조건을 다시 확인한다. 게이트를 통과하면 머지한다.

이 문서는 `@turbo-project/governance` 패키지에 들어 있고 레포에 복사하지 않는다. 설치된 버전의 기준은 `pnpm exec governance criteria`로 본다.

## 원칙

1. 검사를 통과하면 머지해도 안전하다. 안전하지 않았다면 검사를 고친다.
2. 사람은 코드가 아니라 플랜을 본다. "이렇게 만들어도 되는가"는 구현 전에 플랜을 승인하며 정한다.
3. 플랜이 원본이고 PR 본문은 플랜에서 옮긴 결과물이다.
4. 모든 변경은 한 번에 되돌릴 수 있어야 한다. 장애가 나면 고치기 전에 먼저 되돌린다.
5. 사람, 에이전트, 도구 모두 같은 규칙을 따른다.

## 흐름

```
로컬 (작성자 PC)
  워크트리 → 플랜 승인 → 구현 → 검증 명령, 렌더 테스트, 뮤테이션 테스트(바뀐 줄만)
      │
  pnpm exec governance judge --create <gh pr create 인자>   ← PR을 열 때
  pnpm exec governance judge                                 ← push할 때마다(pre-push 훅), base를 바꾼 뒤
      │   1. main으로 가는 PR이면 출처 브랜치를 확인한다. 틀리면 실패로 끝난다
      │   2. 승격·백포트, revert면 판정하지 않는다
      │   3. 새 세션의 Claude가 테스트 없음과 동등 변이를 판정한다
      │   4. PR 본문 맨 위에 판정 결과 한 줄을, `## 수락 기준` 앞에 `## 검증`을 커밋 SHA와 함께 넣는다
      ▼
GitHub: merge-gate (Claude를 쓰지 않는다)
  레포 CI → pnpm exec governance gate
      │   `## 검증`이 지금 커밋에서 통과했는지, 검사를 건너뛰지 않았는지 본다
      ▼
  통과하면 작성자나 에이전트가 머지한다. merge queue가 있으면 큐에 넣는다
```

## 머지 조건

### 로컬에서 판정해 PR 본문에 남기는 것

| 조건 | 누가 |
| --- | --- |
| 동작이 바뀌었으면 바뀐 동작을 확인하는 테스트가 이번 diff에 있다 | 새 세션의 Claude. 기준은 아래 "테스트 없음" |
| 뮤테이션 테스트(바뀐 줄만)에서 살아남은 변이는 모두 동등 변이다 | 새 세션의 Claude. 기준은 아래 "동등 변이" |

### 머지 게이트가 확인하는 것

| 조건 | 실패하면 |
| --- | --- |
| 레포 CI(타입, lint, 테스트, 빌드)가 통과한다 | 고친다 |
| `## 검증`이 지금 커밋에서 판정됐고 결과가 통과다 | 로컬에서 `pnpm exec governance judge`를 다시 돌린다 |
| 이번 diff가 테스트를 건너뛰거나 검사를 끄는 코드를 새로 넣지 않았다: `.skip`, `.only`, `.todo`, `xit`, `eslint-disable`, `@ts-ignore`, `@ts-nocheck`, `Stryker disable` | 지우고 원인을 고친다 |

뮤테이션 테스트는 CI에서 다시 돌리지 않는다. 같은 커밋이면 결과가 같아서, 로컬 결과로 판정한 `## 검증`을 확인하는 것으로 충분하다.

비밀 키 검사, 의존성 취약점 검사는 레포 CI에 둔다. merge queue에서는 레포 CI와 검사 우회만 다시 본다. 판정은 PR에서 이미 확인했다.

### 사람이 하는 일

- 구현 전에 플랜을 승인한다.
- PR 본문 `## 직접 확인할 것`을 본다. 머지를 막지 않는다.
- 에이전트가 같은 곳에서 여러 번 막히면 넘겨받는다.

## 테스트 없음

judge가 이 표를 그대로 읽어 판정 기준으로 쓴다.

| 키           | 신호        | 켜지는 경우 |
| ------------ | ----------- | ----------- |
| missing-test | 테스트 없음 | 동작이 바뀌었는데 바뀐 동작을 확인하는 테스트가 이번 diff에 없다. 동작이 그대로인 정리·이름 바꾸기, 문서·설정·스타일만 바꾼 것, 테스트로 확인할 수 없는 CI·배포 설정은 없음이다. |

## 동등 변이

- 코드를 바꿔도 어떤 값을 넣든 결과가 같아서 테스트로 잡을 수 없는 변이다.
- 작업한 에이전트가 정하지 않는다. judge가 새 세션의 Claude로 판정한다.
- 애매하면 동등 변이가 아니다. 아니라고 판정하면 결과가 달라지는 입력을 같이 낸다. 에이전트는 그 입력으로 테스트를 쓴다.
- 동등 변이로 판정된 것만 이유와 함께 `## 검증`에 남기고, 판정 실패로 보지 않는다.

## 판정하지 않는 PR

보호 브랜치(`main`, `develop`, `staging`)끼리 오가는 승격·백포트 PR, 원래 PR이 이 레포에서 머지된 revert PR. 게이트는 레포 CI와 검사 우회만 본다. 되돌리기를 늦추지 않는다.

## main으로 가는 PR

`main`으로는 보호 브랜치(`develop`, `staging`)나 `hotfix/*`, `release/*`에서만 PR을 연다. 체리픽이나 운영 버그 수정도 `hotfix/*`로 보낸다. 출처가 틀린 PR은 `governance judge`가 판정하지 않고 실패로 끝나며, base를 바꾼 뒤 다시 돌리면 된다. `--create`로 열 때는 PR을 만들지 않는다.

## revert

revert PR 본문에 원래 PR과 되돌린 이유를 쓴다(PR 템플릿의 revert 칸). 원인 분석은 사용자에게 영향이 간 장애이거나 같은 일이 반복될 때만 하고, 결과는 테스트나 게이트 검사로 남긴다.

## 적용 뒤 사람이 할 설정

보호 브랜치에 ruleset을 건다. 켜는 순간 팀의 머지 방식이 바뀌므로 팀에 알리고 켠다.

- PR 필수, 직접 푸시 금지
- 필수 검사는 `merge-gate` 하나. 레포 CI와 `governance gate`를 이 잡 아래에 둔다
- 필요 승인 수 0, Code Owner 승인 끔

## 기준 개정

- 머지 뒤 되돌린 변경이 나오면, 그 유형을 막을 테스트 규칙이나 게이트 검사를 더할지 본다.
- 모든 레포의 개정은 이 문서를 고치는 turbo-project PR로 한다.
