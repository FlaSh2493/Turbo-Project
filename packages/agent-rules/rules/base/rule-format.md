# 규칙 파일 형식

레포 규칙 파일을 추가하거나 고칠 때, 공통 규칙을 바꾸거나 끌 때 따른다.

## [RULEFILE-SPLIT] 공통 파일과 레포 파일

- 레포 규칙 파일은 `.agents/rules/custom/`에 둔다. `AGENTS.md`의 `## 규칙 파일`에 "언제 읽는지"와 함께 링크한다.
- 같은 주제의 공통 파일이 있으면 이름을 같게 하고(`common/fsd.md` ↔ `custom/fsd.md`) 첫 문단에 공통 파일을 링크한다. 레포 파일에는 이 레포의 값과 추가 규칙만 쓴다. 공통 파일의 문장을 옮겨 쓰지 않는다.
- 제품 동작은 규칙에 쓰지 않는다. 코드와 테스트가 보여 준다.

## [RULEFILE-EXCEPTION] 공통 규칙 바꾸기와 끄기

- 공통 규칙을 바꾸거나 끄라는 요청은 `common/`에서 해당 규칙의 ID를 찾아 `AGENTS.md`의 `## 예외`에 쓴다. 바꾸기는 `- [ID] 이 레포에서는 …. 이유: …`, 끄기는 `- [ID] 끈다. 이유: …`다. 공통 문서는 그대로 두고, 예외가 우선한다.
- 해당하는 규칙이 여럿이거나 확실하지 않으면 후보 ID와 문장을 보여주고 묻는다.
- 해당하는 공통 규칙이 없으면 예외가 아니라 레포 규칙으로 추가한다.
- 🔒 규칙이면 쓰지 않고 이유를 알린다.

## [RULEFILE-CONTENT] 넣을 것과 넣지 않을 것

- 넣는다: 코드만 읽어서는 알 수 없고 모르면 깨뜨리는 것, 이 레포에서 실제로 났던 사고와 날짜·커밋, 이상해 보이지만 의도된 코드.
- 넣지 않는다: 린트·타입·테스트가 막는 것, 코드를 열면 보이는 것, 일반 상식, 근거 없는 추측.

## [RULEFILE-SHAPE] 모양

- frontmatter `paths`에 적용할 경로 glob을 둔다. 공통 파일은 `when`에 블록 목록에 붙일 "언제 읽는지"를 둔다.
- 15~60줄. 넘으면 주제로 나눈다.
- 한 문장에 규칙 하나, "~한다", "~하지 않는다"로 끝낸다.
- 근거 소스 파일은 상대 경로로 링크한다. `custom/`에서 레포 루트는 `../../../`다.
