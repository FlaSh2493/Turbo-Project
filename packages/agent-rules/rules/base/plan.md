# 플랜

플랜을 쓸지는 `[BASE-WORK]` 2단계에서 정한다. 이 파일은 쓰는 법과 찾는 법만 다룬다.

| 문서      | 위치                                       | 담는 것                                        | 수명                          |
| --------- | ------------------------------------------ | ---------------------------------------------- | ----------------------------- |
| 변경 요청 | Jira 이슈                                  | 이번에 무엇을 바꾸는가                         | 변경 하나                     |
| 플랜      | Claude Code 기본 플랜 위치(`~/.claude/plans/`) | 이번 변경의 설계·구현 계획·QA 시나리오       | PR이 머지되면 지운다          |
| PR 본문   | GitHub PR                                  | 플랜에서 옮긴 결과물과 검증 결과               | 남는다                        |

## [PLAN-WRITE] 쓰는 법

- 플랜은 Claude Code 플랜 모드로 쓰고, 이 작업의 워크트리에서 승인받는다. 레포에 커밋하지 않는다.
- 출처, 현재 상태, 영향받는 곳(고친 코드를 같이 쓰는 화면, 이동 경로, API, 작업), 구현 단계, 검증 순서, QA 시나리오로 쓴다. QA 시나리오 양식은 [qa-scenario.md](qa-scenario.md)를 따른다.
- 플랜이 원본이다. 작업 중 수락 기준이나 QA 시나리오가 바뀌면 플랜을 먼저 고치고, PR 본문은 플랜에서 다시 옮긴다.
- 현재 동작은 코드와 테스트로 판단한다. 지난 플랜을 모아 추론하지 않는다.

## [PLAN-FIND] 찾는 법

1. 대화에 이번 작업의 플랜이 있으면 그 플랜을 쓴다.
2. 없으면 사용자에게 받은 정보(플랜 경로, 티켓 키, 기능 이름)로 Claude Code 기본 플랜 위치에서 찾는다. 파일 이름은 Claude Code가 붙여서 정확히 맞지 않으므로 파일 내용도 검색한다.
3. 후보가 여럿이거나 없으면 고르지 말고 사용자에게 묻는다. PR 본문으로 플랜을 대신하지 않는다.
