# QA 시나리오

사용자가 이 시나리오대로 화면을 직접 본다.

## [QA-WHEN] 쓰는 때

- 화면, 이동, 인터랙션, 권한별 분기가 바뀌는 작업에 쓴다. 내부 리팩터, API·타입 변경, 문서 변경에는 쓰지 않는다.
- 플랜이나 PR 본문 안에 둔다. 스펙에는 두지 않는다.
- 영향받는 흐름 스펙이 있으면 그 흐름을 회귀로 넣는다.

## [QA-FORM] 양식

```markdown
## QA 시나리오

- 대상: <로컬 | URL>
- 계정/역할: <어떤 계정으로 보는지>

### 흐름

1. <사용자가 하는 일>

### 수락 기준

- <화면에서 눈으로 확인할 수 있는 결과>
```

## [QA-WRITE] 쓰는 법

- 흐름은 사용자가 하는 일로 쓴다. 셀렉터, 클래스명, 버튼 위치는 쓰지 않는다.
- 수락 기준은 요구사항 출처에서 가져오고, 화면에서 판정할 수 있는 문장으로 쓴다.
- 권한·빈 값·실패 응답처럼 분기가 있으면 분기마다 흐름을 나눈다.
