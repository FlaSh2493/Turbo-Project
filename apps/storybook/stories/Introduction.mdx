## 🎨 Agentic Design System

> AI Agent 친화적인 React 디자인 시스템 라이브러리

이 라이브러리는 AI 에이전트가 쉽게 이해하고 활용할 수 있도록 설계된 React 컴포넌트 라이브러리입니다.
Radix UI 기반의 Headless 패턴과 Compound Component 구조를 활용하여 접근성과 커스터마이징을 모두 보장합니다.

---

## 핵심 원칙

### 1. Headless UI 기반

모든 복잡한 컴포넌트는 `headless/` 훅을 통해 상태 로직을 분리합니다.

```tsx
import { useModal } from '@turbo-project/afds/headless'

const { open, setOpen, toggle } = useModal()
```

### 2. Compound Component 패턴

Modal, Toast, Select 등 복잡한 UI는 조합 가능한 하위 컴포넌트로 구성됩니다.

```tsx
<Modal.Root>
  <Modal.Trigger>
    <Button>열기</Button>
  </Modal.Trigger>
  <Modal.Portal>
    <Modal.Overlay />
    <Modal.Content>
      <Modal.Header>
        <Modal.Title>제목</Modal.Title>
      </Modal.Header>
      <Modal.Body>내용</Modal.Body>
      <Modal.Footer>
        <Modal.Close asChild>
          <Button>닫기</Button>
        </Modal.Close>
      </Modal.Footer>
    </Modal.Content>
  </Modal.Portal>
</Modal.Root>
```

### 3. 시맨틱 데이터 속성

모든 컴포넌트는 `data-slot` 속성으로 역할을 명시합니다.

```html
<button data-slot="button" data-variant="default" data-size="md">
  Click me
</button>
```

## 다른 디자인시스템과 공존 (`.afds` 스코프)

이미 Ant Design·MUI 등 **다른 디자인시스템으로 만든 화면**에 AFDS를 얹을 때 필요합니다(예: 기존 앱에 AFDS 챗봇 위젯 추가, Module Federation remote). 전역 `@turbo-project/afds/styles`를 쓰면 AFDS의 Tailwind preflight(전역 reset)가 host 화면 전체로 번져 기존 UI가 깨지고, 모달·팝오버는 `document.body`로 빠져나가 스타일을 잃기 때문입니다.

해결은 두 단계 — 전역 스타일 대신 **스코프된 스타일**을 쓰고, AFDS UI를 `<AfdsScope>`로 감쌉니다:

```tsx
import '@turbo-project/afds/styles/scoped' // ① 전역 styles 대신
import { AfdsScope } from '@turbo-project/afds/scope'

<AfdsScope>
  {/* ② 이 안의 AFDS·오버레이만 .afds 스코프 스타일을 받음 */}
  <Chat />
</AfdsScope>
```

그러면 preflight·디자인토큰·오버레이가 모두 `.afds` 안에서만 동작하고 host 화면은 안전합니다. (단독으로 AFDS만 쓰는 앱이면 기존 `@turbo-project/afds/styles`를 그대로 두면 되고, opt-in이라 아무것도 바뀌지 않습니다.)

### 자주 겪는 문제

- host 컴포넌트를 `<AfdsScope>` **안**에 넣으면 이번엔 그 컴포넌트가 AFDS preflight에 깨집니다 → host는 `.afds` **밖**에 두세요.
- 전역 `styles`와 `styles/scoped`를 **한 페이지에 동시 import 하지 마세요**(전역이 스코프 격리를 무효화).
- host가 이미 Tailwind를 쓰면 유틸리티 class(`text-sm` 등)가 겹칠 수 있으나, 변수 기반이라 대개 무해합니다.

시각 예시·문제 재현과 전체 가이드는 사이드바 **AFDS / Scope / AfdsScope** 스토리(Docs 포함)를 참고하세요.

## 에이전트를 위한 리소스

### Zod 스키마

```tsx
import { ButtonPropsSchema, InputPropsSchema } from '@turbo-project/afds/schemas'

// 런타임 Props 검증
const validatedProps = ButtonPropsSchema.parse({
  variant: 'default',
  size: 'md',
})
```

### 메타데이터 파일

- `manifest.json` - 모든 컴포넌트의 Props, 슬롯, 메타데이터
- `llms.txt` - LLM을 위한 진입점 문서
- `llms-full.txt` - 전체 상세 명세
- `llms-components.txt` - 컴포넌트 목록 요약

## 컴포넌트 카테고리

### Foundation

- Colors - 색상 팔레트
- Typography - 타이포그래피

### Components

- **Button** - 기본 클릭 요소
- **Input** - 텍스트 입력
- **Modal** - 대화 상자
- **Toast** - 알림 메시지
- **Select** - 선택 드롭다운
- **CheckBox** - 체크박스
- **RadioGroup** - 라디오 버튼 그룹
- **Tooltip** - 툴팁
- **Popconfirm** - 확인 팝오버

### Primitives

- Spinner - 로딩 스피너
- Progress - 진행 표시
- Badge - 배지

### Headless Hooks

- `useModal` - 모달 상태 관리
- `useToast` - 토스트 상태 관리
- `useTooltip` - 툴팁 상태 관리
