# 테스트

새로 쓰거나 고치는 테스트에 적용한다. 엣지케이스 점검은 `[BASE-WORK]` 2단계를 따른다.

## [TEST-NAME] 규칙을 문장으로 먼저 뽑는다

- 소스의 규칙(분기·경계·오류 경로)을 먼저 문장으로 뽑고, 그 문장을 테스트 이름으로 쓴다. 예: "계정이 1개면 단수로 말한다".

## [TEST-ASSERT] 동작을 단언한다

입력→출력과 동작을 단언한다. 다음은 쓰지 않는다.

- 소스의 상수·라벨을 테스트에 그대로 옮겨 적기
- 사용자 문구 전체 고정. 구조와 핵심 조각만 본다. 문구가 요구사항인 곳(법적 안내 등)만 예외다
- 구현의 호출 순서나 mock 인자에 묶기
- 이미 있는 케이스의 부분집합, 타입이 보장하는 것

## [TEST-ODD] 이상한 동작은 고정하지 않는다

- 테스트를 쓰다 소스가 이상해 보이면 테스트로 고정하지 않고 사용자에게 알린다. 이상한 동작을 테스트로 못 박으면 버그가 명세가 된다.
