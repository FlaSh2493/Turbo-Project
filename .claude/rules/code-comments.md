# 주석 작성 규칙

주석은 **코드가 말하지 못하는 것만** 적는다.

## 적는다

- **왜** — 의도, 근거, 거부한 대안. 코드는 「무엇을」만 말한다
- **함정** — 비자명한 제약, 바꾸면 조용히 깨지는 것
- **출처** — 외부 규격이나 이슈 번호가 판단의 근거일 때

## 적지 않는다

- 코드가 이미 말하는 것 — `getUser()` 위의 `// 사용자를 조회한다`
- 변경 이력 — git 이 한다
- 장식 — 구분선, 섹션 배너, `=====`, 이모지 나열
- 삭제된 것을 현재형으로 말하는 문장

## 줄일 것은 길이가 아니라 되풀이다

코드가 이미 말하는 것을 지우면 대부분 한두 줄이 된다.

**함정과 근거는 길어도 남긴다.** 바꾸면 조용히 깨지는 것은 **바꾸는 사람 눈앞에** 있어야 한다 — `docs/` 로 빼면 그것이 지키는 코드에서 떨어진다.

배경 설명이 길면 그건 문서다. `docs/` 에 쓰고 한 줄로 링크한다.

## 수치를 박지 않는다

`// 위반 22건` 같은 설명용 값은 다음 커밋에 낡는다. **기준 커밋을 함께** 적거나 검사가 계산하게 한다.

**예외 — 값 자체가 정본인 상수.** 래칫 상한·기준 명부·기대 집합은 그대로 둔다. 계산하게 만들면 검사가 자기 값을 따라가 **항상 통과한다**(`packages/afds/scripts/__test__/rule-globs.test.ts:180` 이 그 순환을 적어 뒀다).

## JSDoc 은 대상이 아니다

공개 API·Storybook 문서용 JSDoc 은 소비자가 읽는 산출물이다. 기존 섹션은 API 가 바뀌어도 지우지 않고 내용만 갱신한다.
